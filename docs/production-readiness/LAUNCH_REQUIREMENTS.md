# Fixed launch acceptance rubric and persistent requirements

Established from the 2 November 2026 audit at clean `4cf13cb`, before this continuation's scoring. This rubric is fixed for this remediation cycle; new evidence changes the levels, not the scoring rule. No score authorizes deployment/publication or bookings.

Each of ten equally weighted domains contributes up to one point. Evidence level **0** = absent/unverified; **1** = implemented/prepared with only limited component evidence (0.25); **2** = meaningful local verification, required external outcome open (0.5); **3** = required external scope verified with only documented minor limitations (0.75); **4** = all required scope verified (1). Score is sum(level / 4), out of ten. Local builds, synthetic data and source review cannot exceed level 2. This makes the existing score reproducibly **4.00/10**, rather than treating it as an average of checklist ticks.

**9/10 requires score ≥9 AND every critical acceptance gate below Verified.** Any known security/safety defect, unverified recoverable source backup, missing actual release candidates, missing real-device trip, required delivery failure or missing legal/operator approval prevents 9/10 regardless of the arithmetic. Only minor documented issues may remain. An external partial pass never closes an unobserved gate.
